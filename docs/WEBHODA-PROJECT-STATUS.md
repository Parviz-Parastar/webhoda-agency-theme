# ۱. معرفی پروژه

WEBHODA یک برند فعال در حوزه دیجیتال مارکتینگ، توسعه فروش، طراحی و توسعه وب‌سایت، تجارت الکترونیک و رشد کسب‌وکار است.

هدف پروژه، ساخت یک وب‌سایت اختصاصی، حرفه‌ای، توسعه‌پذیر و بین‌المللی برای معرفی خدمات و توانمندی‌های WEBHODA است.

### فلسفه و ارزش‌های برند

- هدایت الهی به‌عنوان محوریت فکری و اخلاقی برند
- خدمت صادقانه و امانت‌دارانه به مشتریان
- کمک به رشد فروش و توسعه کسب‌وکارها
- خلق ارزش اقتصادی و ثروت پایدار
- استفاده از فناوری، هوش مصنوعی و بازاریابی نوین
- رعایت صداقت، عدالت و مسئولیت‌پذیری

# ۴. تقسیم وظایف و روش همکاری

### Claude — برنامه‌نویس اصلی

مسئولیت‌ها:
- بررسی فایل‌های مرتبط
- انتخاب راهکار فنی مناسب
- توسعه و اصلاح کد
- ارائه کد کامل فایل‌های تغییرکرده
- ارائه چک‌لیست آزمایش
- اعلام موارد آزمایش‌نشده

### ChatGPT — مدیر پروژه و بازبین

مسئولیت‌ها:
- مدیریت مراحل پروژه
- مشاوره معماری و فناوری
- مشاوره UI/UX
- بررسی خروجی Claude
- بازبینی کد و شناسایی مشکلات
- طراحی چک‌لیست کنترل کیفیت
- ثبت وضعیت پروژه و تصمیمات

### کاربر — اجرا و تأیید

مسئولیت‌ها:
- جایگزینی دستی فایل‌ها
- اجرای سایت در LocalWP
- بررسی نتیجه در مرورگر
- گزارش مشکلات
- تأیید نهایی هر مرحله

**محدودیت مهم:** Claude Chat رایگان استفاده می‌شود. هیچ دسترسی مستقیم Claude به فایل‌های محلی، ترمینال، Git یا امکان ویرایش خودکار فایل‌ها فرض نمی‌شود.

## چرخه کاری استاندارد

۱. تعیین یک هدف مشخص برای مرحله فعلی.

۲. تهیه یک پرامپت کامل و آماده ارسال به Claude.

۳. بررسی فایل‌های مرتبط توسط Claude و ارائه کد کامل.

۴. بررسی خروجی Claude توسط ChatGPT.

۵. جایگزینی فایل‌ها و آزمایش توسط کاربر.

۶. تأیید نتیجه و ثبت وضعیت.

## قوانین همکاری

- در هر مرحله فقط یک هدف مشخص دنبال می‌شود.
- از بررسی دوباره کل پروژه بدون ضرورت خودداری می‌شود.
- فقط فایل‌های مرتبط با مرحله فعلی بررسی و تغییر داده می‌شوند.
- کد فایل‌های تغییرکرده باید کامل و قابل جایگزینی باشد.
- تغییرات غیرضروری در فایل‌های قبلی ممنوع است.
- موارد آزمایش‌نشده باید صریحاً مشخص شوند.
- هیچ تغییری در فایل محلی بدون تأیید کاربر انجام‌شده تلقی نمی‌شود.
- تصمیمات قبلی پروژه حفظ می‌شوند، مگر اینکه کاربر تغییر آن‌ها را تأیید کند.
- توضیحات تکراری و رفت‌وبرگشت‌های غیرضروری باید به حداقل برسند.

## قانون جایگزین هنگام محدودیت ابزار

اگر ابزارهای ChatGPT برای ایجاد، ویرایش یا تحویل فایل با محدودیت مواجه شدند:

۱. کار متوقف نشود.
۲. محتوای کامل فایل در قالب متن ارائه شود.
۳. متن به‌صورت آماده کپی و ذخیره‌سازی باشد.
۴. نام و پسوند فایل مشخص شود.
۵. کاربر شخصاً متن را به فایل با قالب موردنظر تبدیل کند.

# ۸. دسترس‌پذیری — گام A

Claude برای دو فایل کد کامل پیشنهادی ارائه کرده است.

### فایل اول: `header.php`

تغییر پیشنهادی:
- افزودن Skip Link
- متن: «پرش به محتوای اصلی»
- مقصد: `#site-content`

### فایل دوم: `style.css`

تغییرات پیشنهادی:
- حلقه فوکوس دولایه Navy/Gold
- استایل فوکوس لینک‌ها و کنترل‌ها
- `:focus-within` برای فرم جست‌وجو
- اصلاح مشکل بریده‌شدن فوکوس دکمه جست‌وجو
- پشتیبانی از `prefers-reduced-motion`

### وضعیت فعلی

**کد دریافت شده؛ اما جایگزینی و آزمایش در LocalWP هنوز تأیید نشده است.**

### چک‌لیست آزمایش

- [ ] مشخص شود آیا کدهای جدید دو فایل جایگزین شده‌اند.
- [ ] اولین Tab در پنجره ناشناس Skip Link را نشان دهد.
- [ ] Enter روی Skip Link به محتوای اصلی برسد.
- [ ] فوکوس دکمه جست‌وجو بریده نشود.
- [ ] فوکوس فیلد جست‌وجو دور کل فرم دیده شود.
- [ ] حلقه فوکوس روی هدر تیره، Hero، لینک‌ها و دکمه‌ها قابل مشاهده باشد.
- [ ] نتایج جست‌وجو در عرض موبایل زیر ۳۸۰ پیکسل بررسی شود.
- [ ] رفتار `prefers-reduced-motion` در مرورگر بررسی شود.
- [ ] در صورت نیاز، فوکوس عنصر اصلی با `tabindex="-1"` بررسی شود.
